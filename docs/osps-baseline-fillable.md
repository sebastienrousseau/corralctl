# OSPS Baseline — self-assessment

**Criteria version:** v2026.02.19. **Project:** [corral on bestpractices.dev](https://www.bestpractices.dev/en/projects/13455).

This file is the working copy of corral's OpenSSF Baseline self-assessment.
Submitting it makes a **public attestation under the maintainer's identity**,
so every justification below states something checkable in this repository,
and links to the file or setting that backs it.

## How to submit

Each level has a prefilled link. Opening it while signed in populates that
level's form; nothing is saved until **Save (and continue)** is clicked, so
the answers can be read on the page before they are committed.

The links point at project 13455 directly. Do not replace them with the
`/projects?as=edit&url=…` form, which resolves a project by URL and can
create a duplicate entry rather than editing this one.

## A warning worth keeping

An earlier version of this file was written against an older criteria set.
The criterion **identifiers were reused** when the standard moved to
v2026.02.19, but several of the **questions changed underneath them** — so
roughly half the Level 1 answers argued for something the criterion no longer
asked. `OSPS-BR-01.01` had become "sanitize untrusted CI metadata" while the
answer still described commit signing; `OSPS-QA-02.01` had become "provide a
dependency list" while the answer quoted test coverage.

Nothing was submitted, and the answers below are written against the current
questions. **When the criteria version changes, re-read the questions before
trusting the answers**, because the identifiers alone will not tell you they
have moved.

## What is deliberately not claimed

`OSPS-AC-01.01` is left unanswered. It asks whether multi-factor
authentication is required to reach sensitive resources, which is a property
of the maintainer's own GitHub account. Nothing in this repository can
establish it, so it is for the maintainer to answer rather than something to
assert on their behalf.

Six Level 3 criteria are marked **Unmet**, and five of those are the same
shape: the practice exists but is not written down.

| Criterion | What is missing |
|:----------|:----------------|
| `OSPS-BR-07.02` | A secrets policy covering storage, access and rotation |
| `OSPS-VM-04.02` | A published VEX document |
| `OSPS-VM-05.01` | A stated remediation threshold for dependency findings |
| `OSPS-VM-05.02` | A written release policy for dependency findings |
| `OSPS-VM-06.01` | A stated remediation threshold for static-analysis findings |
| `OSPS-QA-07.01` | A non-author reviewer — needs a second maintainer, not a document |

Marking any of these Met would be claiming a policy that a reader could not
find.
